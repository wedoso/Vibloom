# Independent mobile listening room

The `codex/mobile-ui` branch preserves the existing desktop implementation and the accepted first iOS file-picker fix. `index.html` boots `src/adaptiveEntry.ts`, which selects one entry before rendering. Electron, its bridge and `vibloom:` always load `src/main.tsx`; desktop browsers retain that entry even in narrow windows. iPhone, iPad and Android load `src/mobile/main.tsx`. Rotation never changes the selected entry or recreates playback. Browser-only `?ui=mobile` / `?ui=desktop` allow inspection.

Mobile uses the existing Vibloom icon, companion palettes, serif editorial headings and Lucide icons. Player is the initial page. Authentic Live2D is always present in Player, including an empty room. Only Player and Library are workspaces. The upper-left menu opens a navigation drawer for Player, Library, Queue, Storage and Companion; closing or changing workspace returns to the room without rebuilding audio. Queue and Storage are auxiliary drawers, not workspaces. There is no persistent bottom navigation. The companion instance survives navigation; hidden pages preserve stage dimensions so the shared camera does not animate from a zero-size canvas. Mobile supports A/B only: original A sits left of the character and comparison B sits right. B uses comparison slot 1; old slots 2–8 remain stored but are neither shown, decoded, included in playback duration nor available for vocal preparation. The file picker imports into B or explicitly replaces it; switch to A before replacing B. No track bank is shown. A tap only selects the audio; track management and operation sheets are opened explicitly from Listening options. Waveforms and technical metadata stay off the main room. A compact upper-right camera/microphone pill replaces the tall mobile toolbar. The camera button unfolds the actual automatic/locked, portrait and wide controls in the same row, keeping them clear of A/B circles on short screens. Selection, outside taps and Escape close the options; selection/Escape return keyboard focus to the camera trigger. Escape closes camera options before leaving Focus. The companion chooser contains only model choices; camera and vocal actions live on the stage. Mobile hides the greeting button and portals a real MicVocal control into that slot without editing shared stage code; the action opens the actual A/B preparation sheet, shows enabled/preparing state and is disabled without a song. Mobile only restyles and labels the existing camera buttons; selected and locked states come from the real stage. The native framing callbacks remain unchanged; only mobile presentation and accessible labels change. Synced lyrics are in the main player, center and fill progressively on the playback clock, and support tap-to-seek, touch browsing, resume-follow and an expanded view. Resizing recenters the active lyric without moving the document. Plain TXT lyrics remain readable and can be timestamped. A persistent bottom transport exposes a directly tappable/draggable native range. Dragging previews time without seeking on each movement; release commits once, cancelled gestures discard the preview, and keyboard input seeks directly. Playing and paused states are retained. The same transport survives Player/Library navigation; portrait volume and shuffle/repeat remain in Listening options. Focus mode opens a distinct Player view: a compact song/exit header, more space for the companion, hidden source controls, retained lyrics and bottom transport. The real shared stage receives focusMode, while the model and audio instances persist. From Library, Focus opens Player. An always-visible exit and Escape leave the view; Escape dismisses an open panel first. Library, albums, queue and lyrics timing retain touch-specific layouts. EQ, mastering and Remaster are unavailable in mobile; track sheets show a desktop recommendation and an explicit desktop link, which uses the separate desktop library. The mobile workspace exposes no processing API or tools component. The shared Live2D rhythm variables drive the desktop circular disc and scale formula; mobile scopes its gradient-mask styling and honors reduced motion.

Landscape (at least 600px wide) follows the desktop composition: lyrics and Live2D in parallel columns, a collapsed upper-left navigation menu, and a fixed bottom transport showing song/album identity, seek, shuffle, repeat, focus and volume. Queue and Storage become right-side drawers. Portrait divides the available height between the touch orbit and internally scrolling lyrics above a fixed bottom transport. Library retains that same transport with song identity, and the companion stays mounted when switching workspaces. Storage distinguishes clearing the queue, clearing cached audio while keeping albums/lyrics, and resetting the mobile library.

Mobile styles and component trees load independently. Desktop `LibraryApp`, desktop CSS, main entry, Electron code, audio engine and comparison workspace are unchanged by this mobile iteration. Shared code is reused without modifications. Mobile IndexedDB (`vibloom-mobile-library`, state/audio stores) and OPFS (`vibloom-mobile-tracks`) use separate namespaces. An IndexedDB byte-record fallback supports browsers whose OPFS or File-backed Blob writes fail. Mobile clearing never deletes desktop namespaces. Browser quota is still shared by origin, and the mobile library needs its own imports.

Playback restoration uses one engine path for Play and seek, including Safari's `interrupted` state. Native resume waits are cancellable and limited to twelve seconds to accommodate output-route handoffs; a resolved `resume()` promise must also reach the running state before sources are scheduled; failures release the broken audio graph while retaining decoded tracks, A/B selection and position for a new Play tap. Mobile checks context state and clock progress after foreground wakeups and during visible playback. A clock stalled for five seconds triggers one automatic graph rebuild at the saved position; continued failure leaves a paused, retryable player instead of repeatedly rebuilding. Healthy background playback and explicit pauses are preserved. `tests/playback-recovery.test.mjs` covers interruption, hung resume, cancellation, graph replacement, lifecycle events, stalled clocks and the mobile hook's busy/error state. Physical-device interruption testing remains necessary.

Mobile vocal lip sync uses the shared Spleeter worker and VocalJobStore, MotionSync vowel analysis, useVocalPlayback and MusicLipSync with desktop. Mouth poses are sampled before model rendering; centered shape smoothing avoids an additional delayed transition. Listening options, A/B track sheets and song menus open a per-source preparation sheet. Original songs can prepare independently in the background without loading/pausing the player; comparisons use the existing guarded decode path. Preparation shows model download/analysis progress, cancellation, errors and retry; it does not change the audio you hear. Ready data auto-enables and follows the actual audible source and Web Audio clock. Silence, pause, suspended context, mute and unprepared sources sample a silent pose. Seek/source changes are checked against the real Cubism mouth opening and shape parameters for both companions.

Analysis version 4 is saved separately and referenced by the mobile track/comparison snapshot; per-source disabled preferences use only `vibloom-mobile-disabled-vocals`. New source identities never inherit old mouth data. Replacing/removing a source cancels its jobs; removing a song/reset cancels pending work and removes its preferences. Cache clearing cancels preparation while keeping completed vocal timing. The shared pinned model cache is reused and never deleted by mobile clearing. First preparation downloads approximately 37.5 MiB of pinned Spleeter FP16 weights. Mobile prefers WebGPU, falls back to single-thread WASM CPU only if GPU initialization fails, and releases GPU resources every 24 seconds of audio. CPU and whole-song GPU analysis passed on an iPhone 17 Pro; processing requires the page to stay open. Player shows one stage progress ring per current-song task; Library retains the header task shortcut. Desktop uses the same model, chunking, MotionSync and conservative sustained-vowel gap repair.

`node scripts/check-mobile-vocals.mjs --playwright-module /absolute/path/to/playwright/index.mjs --model-dir /absolute/path/to/spleeter` runs the actual browser workers against the pinned model cached locally for repeatable tests. It verifies download/cancel/network-error/retry, original and silent comparison analysis, responsive playback, both real rigs, source switching/seeking, closure on pause/disable and persisted analysis/preferences. Results belong under ignored `outputs/mobile-ui/`.

## Mobile pinch and compact lyric editing

Two touch pointers on the model canvas change the actual shared camera zoom (0.78–4×). `modelPinch.ts` is a mobile adapter to the existing wheel controller, retaining native camera presets without modifying the shared renderer. One finger still drives gaze; mouse pointers do not pinch. Pointer capture, third-finger rejection, cancellation, resize, background and unmount cleanup prevent stuck gestures. Only the mobile model canvas disables browser touch pan/zoom. The percentage readout disappears after the camera settles. Portrait/Wide/Automatic controls remain available to restore framing.

The lyric sheet shows a compact timestamp/text list. Selecting a line chooses the target for stamping; its pencil unfolds only that line's text and seconds input. Direct seek and preview play/pause sit at the top; Stamp & next and Save stay above the safe area and keyboard. Add line, bounded undo and LRC/TXT export move into More. Listening options → Lyrics → Edit lyric timing → More lyric actions offers Export LRC and Export TXT. LRC requires completed, valid timestamps and retains metadata; TXT contains only lyric text and line breaks, including translations, repeated verses and blank cues, and also works for untimed drafts. Exports use the lyric filename (or song filename as fallback) and UTF-8 text without changing the saved lyrics. Save validates all timestamps and preserves LRC metadata; unsaved close/Escape offers Keep editing or Discard. Changing songs remounts the editor draft. Stamping advances selection without pausing playback. The list scrolls independently and keeps selected/focused fields visible.

`tests/lyrics-export.test.mjs` verifies text-only output and preserved lyric content. After building, `npx electron scripts/smoke-lyrics-export.mjs` checks real mobile LRC/TXT downloads, Unicode filenames/content, untimed TXT and LRC validation with a disposable library profile.

It creates disposable WAV/LRC fixtures in ignored outputs, verifies real Live2D pinch zoom and limits, one/three-finger behavior, presets, save, undo, delete, validation, metadata export, stamping during playback and unsaved Escape. ## Album ordering

Hold a song for 450 ms in an album, drag to an insertion line, and release to save its position. Ordinary swipes scroll the list; dragging near the edge auto-scrolls the active portrait or landscape pane. Cancelled gestures leave the order intact. Filtering preserves hidden album members, and sorting does not change the current song or queue. Keyboard users can move a focused song with Alt + Up/Down.

## Player without lyrics

Without synced or plain-text lyrics, Player reserves only a compact Add lyrics invitation. Portrait gives the remaining height to the companion; landscape narrows the empty lyrics column. Attaching LRC/TXT restores the normal lyric viewport, including in Focus mode.

## Lock-screen and car lyrics (Beta)

**Beta:** Mobile publishes the current timed LRC line in Media Session’s artist field, retaining the song title, album and artwork. It writes only changed lines, reads the actual audio clock independently of visual rendering, follows paused seeks, and restores Vibloom during blank lyric segments, at track end or on songs without synced lyrics. Plain TXT requires timing before it can be synchronized. Desktop metadata remains unchanged. Lock-screen and Bluetooth display depend on iOS/browser/receiver support; physical-device testing is required, and this is not a dedicated multi-line lyrics protocol.

System progress updates are limited to 1 Hz during normal playback and use the actual audio clock even without React rendering. Play/pause, track changes, explicit seeks and changed lyric lines publish immediately; unchanged playback state is not repeatedly assigned. Album artwork is prepared independently of the phone UI: a decoded, contained 512×512 JPEG with explicit MIME type and dimensions, reused for consecutive songs in the same album. Late/cancelled conversions cannot overwrite a newer song, and artwork arrival preserves the active metadata object and lyric. Decode failures leave playback usable. These changes reduce unnecessary native updates; Tesla redraw and Bluetooth artwork delivery still require receiver testing.

`tests/media-publishing.test.mjs` covers native-update frequency, transport changes, lyric/position synchronization, bounded image decode, cover races, cancellation and failures. `npx electron scripts/smoke-media-publishing.mjs` verifies real canvas/JPEG decode, native MediaMetadata artwork and native position update counts in a disposable profile.

## Offline startup, lyric shortcuts and playback help

Production HTTP(S) builds install a versioned service worker scoped to the deployment directory. The complete app shell and both companions are cached before offline readiness is reported. Cached songs stay in the existing library stores; remote weights and large inference runtimes are not downloaded during initial setup. Storage → Offline access reports preparation, readiness, incomplete setup/retry and available updates. An installed shell is checked before any network registration attempt, so a cold offline launch can report readiness. Browser storage can still be cleared; cached music remains separate from backups.

Updates install into a separate cache and wait. Storage offers Update & reload only while playback is paused. No automatic update reloads a playing page, and older shells remain available to open tabs. The scope and cache names support GitHub Pages subpaths. Development and Electron do not register the web worker. `npx electron scripts/smoke-offline-help.mjs` checks offline startup under `/Vibloom/` with network and HTTP cache disabled, cached audio and companion loading, deferred updates, persisted system-lyrics preferences, direct lyric actions and actual error/retry flows. Screenshots belong under ignored `outputs/offline-help/`.

Player offers Edit lyrics immediately above the lyric viewport. Listening options → Lyrics exposes an edit button and direct Export TXT / Export LRC actions, without opening the timing editor or loading audio. Untimed text can export TXT; LRC requires valid completed timestamps. Desktop Player/Focus lyric panels expose direct exports too.

Listening options → Lock-screen & car lyrics is independent of in-app lyrics. The preference persists with the mobile session; old libraries retain the previous enabled behavior. Turning it off immediately restores the system artist to Vibloom, cancels lyric timers and preserves title, artwork and playback controls. Re-enabling it catches up to the actual playback position.

Storage → Playback status & help is available at any time. A failed playback action also exposes a persistent Details entry. Help distinguishes missing source files, read errors, decode errors, audio-device resume failures/timeouts, stalled clocks and system-control failures, offering reconnect or retry as appropriate. Retry uses the last attempted song/position and rebuilds a failed audio connection without reloading the app. Copy diagnostics shares only app version, online/audio state and at most 24 coded playback stages. It excludes raw exception text, filenames, paths, song IDs, lyrics and audio; clipboard failures offer selectable report text. Reports stay in memory and nothing is uploaded.

### Wireless output clocks

Web Audio scheduling and crossfades retain the render clock. Player progress, lyric timing, end-of-track handling, saved positions and Media Session use a separate output-time estimate: `getOutputTimestamp()` when usable, otherwise reported `baseLatency` plus `outputLatency`, with the render clock as the final fallback. Starts and seeks hold the requested position until the output clock reaches the scheduled audio; pause retains the heard position. The system playback declaration follows output readiness and interruption state even without a React render. Browsers cannot verify that a HomePod is actually emitting sound or expose all receiver buffering.

When WebKit has a declared playback Audio Session (including the mobile standalone app), it uses the native Web Audio Now Playing session without a competing ten-second HTML audio carrier. Chromium/Electron and legacy Safari retain the existing carrier fallback. This avoids giving WebKit a silent media element that can own system progress or output routing. Copyable playback diagnostics now include finite browser-reported output latencies. `npm run desktop:smoke:wireless` exercises the real mobile UI with an injected delayed output clock; it is not HomePod or WebKit device validation.
