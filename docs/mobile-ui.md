# Independent mobile listening room

The `codex/mobile-ui` branch preserves the existing desktop implementation and the accepted first iOS file-picker fix. `index.html` boots `src/adaptiveEntry.ts`, which selects one entry before rendering. Electron, its bridge and `vibloom:` always load `src/main.tsx`; desktop browsers retain that entry even in narrow windows. iPhone, iPad and Android load `src/mobile/main.tsx`. Rotation never changes the selected entry or recreates playback. Browser-only `?ui=mobile` / `?ui=desktop` allow inspection.

Mobile uses the existing Vibloom icon, companion palettes, serif editorial headings and Lucide icons. Player is the initial page. Authentic Live2D is always present in Player, including an empty room. Only Player and Library are workspaces. The upper-left menu opens a navigation drawer for Player, Library, Queue, Storage and Companion; closing or changing workspace returns to the room without rebuilding audio. Queue and Storage are auxiliary drawers, not workspaces. There is no persistent bottom navigation. The companion instance survives navigation; hidden pages preserve stage dimensions so the shared camera does not animate from a zero-size canvas. Mobile supports A/B only: original A sits left of the character and comparison B sits right. B uses comparison slot 1; old slots 2–8 remain stored but are neither shown, decoded, included in playback duration nor available for vocal preparation. The file picker imports into B or explicitly replaces it; switch to A before replacing B. No track bank is shown. A tap only selects the audio; track management and operation sheets are opened explicitly from Listening options. Waveforms and technical metadata stay off the main room. A compact upper-right camera/microphone pill replaces the tall mobile toolbar. The camera button unfolds the actual automatic/locked, portrait and wide controls in the same row, keeping them clear of A/B circles on short screens. Selection, outside taps and Escape close the options; selection/Escape return keyboard focus to the camera trigger. Escape closes camera options before leaving Focus. The companion chooser contains only model choices; camera and vocal actions live on the stage. Mobile hides the greeting button and portals a real MicVocal control into that slot without editing shared stage code; the action opens the actual A/B preparation sheet, shows enabled/preparing state and is disabled without a song. Mobile only restyles and labels the existing camera buttons; selected and locked states come from the real stage. The native framing callbacks remain unchanged; only mobile presentation and accessible labels change. Synced lyrics are in the main player, center and fill progressively on the playback clock, and support tap-to-seek, touch browsing, resume-follow and an expanded view. Resizing recenters the active lyric without moving the document. Plain TXT lyrics remain readable and can be timestamped. A persistent bottom transport exposes a directly tappable/draggable native range. Dragging previews time without seeking on each movement; release commits once, cancelled gestures discard the preview, and keyboard input seeks directly. Playing and paused states are retained. The same transport survives Player/Library navigation; portrait volume and shuffle/repeat remain in Listening options. Focus mode opens a distinct Player view: a compact song/exit header, more space for the companion, hidden source controls, retained lyrics and bottom transport. The real shared stage receives focusMode, while the model and audio instances persist. From Library, Focus opens Player. An always-visible exit and Escape leave the view; Escape dismisses an open panel first. Library, albums, queue and lyrics timing retain touch-specific layouts. EQ, mastering and Remaster are unavailable in mobile; track sheets show a desktop recommendation and an explicit desktop link, which uses the separate desktop library. The mobile workspace exposes no processing API or tools component. The shared Live2D rhythm variables drive the desktop circular disc and scale formula; mobile scopes its gradient-mask styling and honors reduced motion.

Landscape (at least 600px wide) follows the desktop composition: lyrics and Live2D in parallel columns, a collapsed upper-left navigation menu, and a fixed bottom transport showing song/album identity, seek, shuffle, repeat, focus and volume. Queue and Storage become right-side drawers. Portrait divides the available height between the touch orbit and internally scrolling lyrics above a fixed bottom transport. Library retains that same transport with song identity, and the companion stays mounted when switching workspaces. Storage distinguishes clearing the queue, clearing cached audio while keeping albums/lyrics, and resetting the mobile library.

Mobile styles and component trees load independently. Desktop `LibraryApp`, desktop CSS, main entry, Electron code, audio engine and comparison workspace are unchanged by this mobile iteration. Shared code is reused without modifications. Mobile IndexedDB (`vibloom-mobile-library`, state/audio stores) and OPFS (`vibloom-mobile-tracks`) use separate namespaces. An IndexedDB byte-record fallback supports browsers whose OPFS or File-backed Blob writes fail. Mobile clearing never deletes desktop namespaces. Browser quota is still shared by origin, and the mobile library needs its own imports.

## Validation

- `npm run check`: lint and unit/domain tests; one pre-existing desktop hook warning remains.
- `npm run build`: TypeScript and production bundles.
- `npm run desktop:smoke`: Electron desktop entry, native bridge and actual Live2D readiness.
- `node scripts/check-mobile-ui.mjs --playwright-module /absolute/path/to/playwright/index.mjs`: Chromium/WebKit flow and render audit. Playwright is an optional external verification runtime, not a shipped dependency. The audit expects `outputs/mobile-ui/desktop-baseline-dist` containing the retained-picker desktop baseline build.

Workspace, library tab/album, A/B source and sheet entries have short opacity/translation animations; left/right drawers enter from the corresponding side. Audio and Live2D are not keyed to workspace navigation. Picker taps stay synchronous; reduced-motion preference disables transitions and animations.

The audit covers 320/360/390/430/768px portrait and 844×390 landscape, both palettes, long CJK/Latin filenames, legacy nine-source snapshots restricted to A/B without data loss, queue, albums, source/lyrics/storage/companion sheets, focus mode and cache/queue confirmation states, missing files and reduced input viewport. It exercises trusted file-picker clicks, real WAV/LRC import, playback, seek, the real desktop camera capsule, direct pointer scrubbing/release/cancellation, paused keyboard seek, collapsed navigation with Escape/focus return, real Focus stage state and visible exit, Library-to-Player focus, Escape panel priority, entry animations and reduced motion, persistent transport and lyrics clear of the footer, paused seek centering lyrics, touch browsing/follow, cache removal preserving songs/albums/lyrics, repeated warm switching without dialogs, delayed cold reads with old audio continuing, cancellation of superseded selections, audio-driven circular background and reduced motion, A/B-only controls, desktop-feature hint and B replacement, cache reload/playback, rotation and desktop storage sentinels. Desktop geometry is compared against the baseline at 1440/1024/600/390px. Generated HTML report, screenshots and raw evidence belong under ignored `outputs/mobile-ui/`.

These are engine and viewport tests, not physical iPhone Safari/Chrome certification. Verify iCloud Drive, native folder selection, keyboard/safe areas, downloads, codec coverage and background/interruption handling on devices before release. iOS inputs avoid `accept=audio/*` filtering (WebKit bug 242110); directory selection is enabled for identifiable iOS 18.4+ and otherwise offers selecting the files within a folder. Picker availability still depends on OS/browser/provider.

Mobile vocal lip sync reuses the unmodified desktop VocalJobStore, Demucs separation worker, MotionSync vowel analysis, useVocalPlayback sampler and MusicLipSync rig controller. Listening options, A/B track sheets and song menus open a per-source preparation sheet. Original songs can prepare independently in the background without loading/pausing the player; comparisons use the existing guarded decode path. Preparation shows model download/analysis progress, cancellation, errors and retry; it does not change the audio you hear. Ready data auto-enables and follows the actual audible source and Web Audio clock. Silence, pause, suspended context, mute and unprepared sources sample a silent pose. Seek/source changes are checked against the real Cubism mouth opening and shape parameters for both companions.

Analysis version 4 lives in the mobile track/comparison snapshot; per-source disabled preferences use only `vibloom-mobile-disabled-vocals`. New source identities never inherit old mouth data. Replacing/removing a source cancels its jobs; removing a song/reset cancels pending work and removes its preferences. Cache clearing cancels preparation while keeping completed vocal timing. The shared pinned model cache is reused and never deleted by mobile clearing. First preparation downloads approximately 172 MiB; processing requires the page to stay open and physical phone memory/background behavior remains unverified.

`node scripts/check-mobile-vocals.mjs --playwright-module /absolute/path/to/playwright/index.mjs --model /absolute/path/to/htdemucs.onnx` runs the actual browser workers against the pinned model cached locally for repeatable tests. It verifies download/cancel/network-error/retry, original and silent comparison analysis, responsive playback, both real rigs, source switching/seeking, closure on pause/disable and persisted analysis/preferences. Results belong under ignored `outputs/mobile-ui/`.

## Approved editorial refinement

The implementation adopts the warm editorial Player concept and compact utility grouping, with the same composition in Hong Xi powder blue. The broad real Live2D stage, left/right A/B circles, serif song headings, regular system-font lyrics, subtle dividers and persistent direct playback form one paper surface. Long song names wrap to two lines with CJK serif fallbacks; narrow/short viewports retain stage and lyric space. Library/Albums, Queue/Storage, navigation, import, track, lyrics, vocal and confirmation panels share typography, materials, selected-row tint and button geometry. Collection and album headings are concise; actual list titles remain sans. The new stylesheet is imported only by MobileApp and cannot alter desktop styles.

ImageGen concepts and the secondary-page Library/Queue/Storage alignment board live in ignored `outputs/mobile-ui/player-concepts/`. They are reference images only; the product keeps its actual brand, real model and existing icons. Generated storage guarantees were not adopted; browser persistence remains explicitly subject to browser approval. The render audit includes expanded camera options, minimum camera touch targets and stage/lyric separation.

The mobile character host uses an alpha mask to fade its lower edge into the room, covering both the canvas boundary and the artwork’s own straight edge. Only the character layer fades; the real rhythm disc, camera capsule, A/B circles and lyrics remain separate. The prefixed and standard mask declarations share relative-height stops for short screens, landscape and Focus. Renderer dimensions, model instances and audio stay unchanged.

## Lyric typography and simulator compute check

Room, expanded and plain-text lyrics share the mobile system sans stack, weight 400 and disabled synthetic weight/style. The current timed line uses the existing progressive color fill; it does not change font weight. This avoids the former room-only serif override and expanded view's inherited weight 700. Scoped mobile CSS leaves desktop typography unchanged. Chromium/WebKit checks cover two palettes, four portrait/landscape sizes and both room/expanded views (32 cases), including mixed Latin/CJK text, wrapping and paused tap-to-seek. The iPhone 17 Pro simulator also reports weight 400 in both views.

The current simulator (iOS 27.0) exposes `navigator.gpu`, but `requestAdapter({powerPreference: "high-performance"})` returns null in both the page and a worker. The existing Demucs worker already prioritizes WebGPU and falls back to single-thread WASM; a simulator with no adapter therefore uses CPU inference. Its performance does not establish physical-iPhone performance. First preparation also downloads the pinned 172 MiB weights; prepared timing data is cached per source. This diagnostic does not change the shared inference pipeline or claim a separation speed improvement. Evidence is saved under `outputs/mobile-ui/iphone17-pro-runtime-diagnostic.json`.
