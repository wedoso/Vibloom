# Independent mobile listening room

The `codex/mobile-ui` branch preserves the existing desktop implementation and the accepted first iOS file-picker fix. `index.html` boots `src/adaptiveEntry.ts`, which selects one entry before rendering. Electron, its bridge and `vibloom:` always load `src/main.tsx`; desktop browsers retain that entry even in narrow windows. iPhone, iPad and Android load `src/mobile/main.tsx`. Rotation never changes the selected entry or recreates playback. Browser-only `?ui=mobile` / `?ui=desktop` allow inspection.

Mobile uses the existing Vibloom icon, companion palettes, serif editorial headings and Lucide icons. Player is the initial page. Authentic Live2D is always present in Player, including an empty room. Only Player and Library are workspaces; Queue and Storage open as auxiliary drawers without replacing either workspace. Its instance survives navigation; hidden pages preserve stage dimensions so the shared camera does not animate from a zero-size canvas. The original circle is left of the character; comparisons form an arc on the right. Screens up to 850px high show 3 per bank and taller screens 4, with a numbered bank circle keeping all nine accessible. A tap only selects the audio; track management and operation sheets are opened explicitly from Listening options. Waveforms and technical metadata stay off the main room. Visible Director/Portrait/Wide camera controls mirror the actual shared Live2D camera state. Synced lyrics are in the main player, center and fill progressively on the playback clock, and support tap-to-seek, touch browsing, resume-follow and an expanded view. Resizing recenters the active lyric without moving the document. Plain TXT lyrics remain readable and can be timestamped. A small progress/time control opens seeking; portrait volume and shuffle/repeat remain in Listening options. Focus mode hides track circles while playback and lyrics continue. Library, albums, queue, lyrics timing, EQ/mastering and repair retain touch-specific layouts. The shared Live2D rhythm variables drive the desktop circular disc and scale formula; mobile scopes its gradient-mask styling and honors reduced motion.

Landscape (at least 600px wide) follows the desktop composition: a left Player/Library/Queue/Storage rail, lyrics and Live2D in parallel columns, and a fixed bottom transport showing song/album identity, seek, shuffle, repeat, focus and volume. Queue and Storage become right-side drawers. Portrait retains the touch orbit, transport and full-width lyric area. Library keeps a mini player, and the companion stays mounted when switching workspaces. Storage distinguishes clearing the queue, clearing cached audio while keeping albums/lyrics, and resetting the mobile library.

Mobile styles and component trees load independently. Desktop `LibraryApp`, desktop CSS, main entry, Electron code, audio engine and comparison workspace are unchanged by this mobile iteration. Shared code is reused without modifications. Mobile IndexedDB (`vibloom-mobile-library`, state/audio stores) and OPFS (`vibloom-mobile-tracks`) use separate namespaces. An IndexedDB byte-record fallback supports browsers whose OPFS or File-backed Blob writes fail. Mobile clearing never deletes desktop namespaces. Browser quota is still shared by origin, and the mobile library needs its own imports.

## Validation

- `npm run check`: lint and unit/domain tests; one pre-existing desktop hook warning remains.
- `npm run build`: TypeScript and production bundles.
- `npm run desktop:smoke`: Electron desktop entry, native bridge and actual Live2D readiness.
- `node scripts/check-mobile-ui.mjs --playwright-module /absolute/path/to/playwright/index.mjs`: Chromium/WebKit flow and render audit. Playwright is an optional external verification runtime, not a shipped dependency. The audit expects `outputs/mobile-ui/desktop-baseline-dist` containing the retained-picker desktop baseline build.

The audit covers 320/360/390/430/768px portrait and 844×390 landscape, both palettes, long CJK/Latin filenames, nine sources, queue, albums, source/tool/lyrics/storage/companion sheets, focus mode and cache/queue confirmation states, missing files and reduced input viewport. It exercises trusted file-picker clicks, real WAV/LRC import, playback, seek, visible camera controls reflecting the real shared stage, paused seek centering lyrics, touch browsing/follow, cache removal preserving songs/albums/lyrics, repeated warm switching without dialogs, delayed cold reads with old audio continuing, cancellation of superseded selections, audio-driven circular background and reduced motion, EQ generation, cache reload/playback, rotation and desktop storage sentinels. Desktop geometry is compared against the baseline at 1440/1024/600/390px. Generated HTML report, screenshots and raw evidence belong under ignored `outputs/mobile-ui/`.

These are engine and viewport tests, not physical iPhone Safari/Chrome certification. Verify iCloud Drive, native folder selection, keyboard/safe areas, downloads, codec coverage and background/interruption handling on devices before release. iOS inputs avoid `accept=audio/*` filtering (WebKit bug 242110); directory selection is enabled for identifiable iOS 18.4+ and otherwise offers selecting the files within a folder. Picker availability still depends on OS/browser/provider.

Mobile Live2D uses actual music analysis for movement and the existing portrait/wide/interaction controls. This iteration does not expose vocal preparation for vocal-driven lip synchronization.
